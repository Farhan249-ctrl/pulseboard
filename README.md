# PulseBoard: Production Architecture (MERN)

Team daily pulse check. Users register and log in (JWT), post one pulse per day (mood 1-5 plus a short note), see today's team feed and their own history. An ADMIN sees today's summary (average mood, number of posts, total users).

DevOps project (Docker and Jenkins), Q75, Part 4: Nginx, React, Node.js and MongoDB with Compose, volumes, an env file and HTTPS.

## Architecture

```
User -> Nginx (80/443, only published service)
          |-- /      -> React frontend (nginx:alpine, static build)
          |-- /api/  -> Node.js API (private network)
                           |-> MongoDB 7 (private network, named volume)
```

- Same origin: the frontend calls relative `/api/...` URLs, so there is no CORS.
- Two networks: `edge` (nginx, frontend, api) and `data` (api, mongo; `internal: true`). Mongo has no route to the outside.
- HTTP on 80 redirects to HTTPS. Local demo ports are 8081 (HTTP) and 8443 (HTTPS); on a server they are 80 and 443 through `.env`.
- HTTPS uses a self-signed certificate generated by `scripts/gen-cert.ps1`. Keys are never committed.

## Stack
Node 20, Express, Mongoose, MongoDB 7, JWT (bcryptjs), React 18 + Vite + TypeScript, Nginx 1.27, Docker Compose.

## Run it (Windows PowerShell)
```powershell
copy .env.example .env        # then set real passwords and JWT_SECRET (32+ chars)
.\scripts\gen-cert.ps1        # self-signed cert into certs/
docker compose build
docker compose up -d
docker compose ps
.\scripts\seed-prod.ps1       # admin + demo data
```
Open https://localhost:8443 (accept the self-signed certificate warning).

## Dockerfiles
- `backend/Dockerfile`: multi-stage, `node:20.18-alpine`, `npm ci --omit=dev`, non-root `node` user, healthcheck on `/api/health`.
- `frontend/Dockerfile`: node build stage, then `nginx:1.27-alpine` serving the static build with SPA fallback, healthcheck.
- `nginx/nginx.conf`: edge proxy, TLS, redirect, security headers, gzip.
- `.dockerignore` in backend and frontend; image versions pinned.

## Containers (evidence)
See `docs/evidence.txt` for `docker compose ps`, logs and `docker stats`.

- All four services show `healthy`/running; only Nginx publishes ports.
- Data persistence: `docker compose down` (without `-v`) then `up -d`, and the seeded data (5 users, 3 posts today, average mood 3.7) was still returned by the admin summary.
- Isolation: the API is reachable only inside the Docker network (`docker compose exec nginx wget http://api:4000/api/health` works; no host port is published for the API or Mongo).

Screenshots: `docs/screenshots/` (login, dashboard, admin, compose ps).

## Database
- `db/init/01-create-app-user.js`: creates a least-privilege app user (`readWrite` on the app database only). The API connects as this user, not root.
- Mongoose models: `backend/src/models/User.js` and `Pulse.js`. Pulse has a unique compound index `{user, day}`, so the database itself enforces one pulse per user per day.
- `backend/src/seed.js`: idempotent seed (admin, demo users, sample pulses).

## Backend overview
Express app with JWT auth, zod validation, helmet, rate limiting on auth routes and central error handling. Endpoints: `GET /api/health`, `POST /api/auth/register`, `POST /api/auth/login`, `GET /api/auth/me`, `POST /api/pulses`, `GET /api/pulses/today`, `GET /api/pulses/mine`, `GET /api/admin/summary` (ADMIN only). Details in `docs/backend.md`.

## Frontend overview
Pages: login, register, dashboard (post pulse and team feed), history, admin summary. Token kept in localStorage, one fetch wrapper adds the Bearer token and logs out on 401. Plain CSS design tokens with light/dark themes.
